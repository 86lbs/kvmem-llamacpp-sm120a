## KVMem on Windows RTX 50 (sm_120a) - two routes, measured

This repo now documents **both** KVMem backends on a 12GB RTX 5070 Ti Laptop.

### Route A: NInfer - 27B WORKS (recommended)

Official `kvmem-v0.19.0-rc1-ninfer-windows-rtx50-sm120a.zip` + `Ternary-Bonsai-2-27B` (8.87 GB ternary .ninfer).

| Context | Time | prefill | decode | Retrieval |
|---|---|---|---|---|
| 47.7K | 57 s | 857 tok/s | 51 tok/s | hit |
| 74.9K (3 needles) | 92 s | 848 tok/s | - | 3/3 hit |
| 122.5K | 140 s | 887 tok/s | 44 tok/s | hit |
| **204.1K (max)** | 234 s | 883 tok/s | 43 tok/s | hit |

Weights 6.70 GiB on GPU, KV pool 2560 tokens, host payload 12.5 GB at 204K. Logic test (chicken/rabbit) correct.

Note: the officially recommended IQ3_S artifact is 13.13 GB - too big for 12 GB. The 8.87 GB ternary variant is what fits.

### Route B: llama.cpp - this repo's binary (<=9B only)

| | |
|---|---|
| File | `llama-kvmem-server.exe` |
| Size | 82.9 MB |
| SHA256 | `71143A57F15D0F542BAC4A21C26C7B7F753F34796035137D1D2BF200AE25C24F` |

Verified: 9B Q4_K_M works (44 tok/s). 75K: native 2233 vs KVMem 1799 tok/s. 252K: native 1192 vs **KVMem 1800 tok/s**.

**27B on llama.cpp is broken**: 2-bit i-quant produces garbage on sm_120 GPU (CPU is correct). Ruled out arch suffix, FORCE_MMQ, DISABLE_GRAPHS, -fa off.

### Which to use

- 27B or larger, long context -> **NInfer**
- small models with existing GGUF -> llama.cpp
